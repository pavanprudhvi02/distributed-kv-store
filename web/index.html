Five nodes running the Raft implementation from my distributed key-value store, on a simulated network. Crash the leader or cut the network and watch the cluster elect a new leader without losing a committed write.

      Inside each node

      Each node is the same RaftNode class from src/raft that the server runs, here in its single-threaded mode, driven by a virtual clock instead of its own ticker and applier threads. Messages travel a simulated network with 120 to 280 ms of latency, and each node keeps its log and vote in an in-memory file system so a restarted node recovers them. Timeouts are slowed down (1.5 to 3 s elections, 450 ms heartbeats) so you can watch them. In the real build, each node applies entries to the LSM-tree storage engine and talks to the others over gRPC.
